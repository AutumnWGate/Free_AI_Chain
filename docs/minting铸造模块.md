# minting铸造模块

1. 模块目标
minting铸造管理模块的核心目标是集中管理所有代币铸造 (minting) 相关的操作和逻辑。 
铸造的代币应该在账本中的数据库、区块链、merkletree中都有体现，应当参考当前数据库、区块链、merkletree的代码。

2. 模块功能：
    铸造代币: 实现铸造新代币的功能。
    铸造权限: 采用目前只实现管理员铸造权限，参考src/docs/铸造权限设计构思.md
    铸造验证: 铸造验证逻辑参考src/docs/validator验证模块说明.md
    铸造历史记录: 记录所有铸造事件,通过交易记录实现，参考目前交易记录实现的代码。
    铸造签名：参考src/crypto/signature/signature.rs

3. 开发要求：
   1. minting模块集成在ledger模块中，共用模块中的DB、Merkle树管理 (MerkleTreeManager)、区块管理 (BlockManager)。
   2. 文件及代码应该放在src/ledger/minting目录下。

4. 模块目录结构
src/ledger/minting/
├── mod.rs                  // 模块声明和导出
├── minting_manager.rs      // 铸造管理器，处理铸造请求和核心业务逻辑
├── minting_executor.rs     // 铸造执行器，负责与账本模块交互，更新数据
├── minting_verify.rs     // 铸造验证器，调用 validator 模块进行验证
├── minting_whitelist.rs    // 拥有铸造权限的钱包地址白名单
├── minting_error.rs        // 铸造模块自定义错误类型定义

5. 未来扩展方向
- 更细粒度的权限控制: 实现更复杂的权限规则配置，例如基于代币类型、铸造数量、时间窗口等进行更精细的权限控制。
- 链上治理集成: 将权限配置和角色分配与链上治理系统集成，实现去中心化的权限管理。
- 动态权限调整: 支持动态调整权限配置，例如根据链上事件或治理投票结果实时更新权限规则。
- 权限委托: 允许角色将部分权限委托给其他地址或合约。
- 权限审计和监控: 提供完善的权限审计和监控机制，方便追踪权限变更和异常铸造行为。

6. 发起铸造请求时，应该有的信息格式：
    - 铸造发起者的钱包地址
    - 铸造的代币数量大于0
    - 铸造的代币：默认是FAIC
    - 本次铸造是否锁定：默认是不锁定
    - 本次铸造的解锁时间：默认是立即解锁
